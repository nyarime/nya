## How to read

- **walk+greedy**: interleaved extension order (bad solid input order).
- **sorted+greedy**: extension + content-kind grouping (current `-solid` writer).
- **sorted+optimal**: sorted order with DP optimal parser (`OptimalParse: true`).
- **nya archive**: full `.nya` size including header and central directory.
- **xz / zstd on solid row**: compressed size of the **sorted** solid byte stream (not a tar wrapper).

## Findings

1. **Greedy beats optimal** on structured text and the 120-file solid tree at level 9; optimal remains for highly repetitive streams (`lzma2_optimal_test.go`).
2. **Solid sorting** saves ~0.5% on the interleaved 120-file tree (30.86% → 30.39% compressed stream).
3. **Structured text**: NYA-LZMA2 greedy **beats** xz and 7z on ratio in this run; encode time is still faster than xz.
4. **Solid tree**: ratio within ~1% of xz/zstd on sorted stream; 7-Zip solid encodes much faster.
5. Incompressible ELF-like payloads stay at ~100% regardless of tool.

Reproduce: `NYA_BENCH_WRITE=1 go test -run TestREADMEBenchmarkSuite -timeout 60m -v ./...`

## Solid ZSTD dictionary (levels 3–4)

For text-heavy game packs (configs, shaders, locale), a trained zstd dictionary
on `-solid` archives can beat plain NYA-Zstd. Manual `-dict` or **auto-derived
dict** at solid close — see **`docs/SOLID-DICT.md`** for eligibility and the
offline `zstd --train` workflow.
Regression: `go test -run TestSolidZstdDict -v ./...`
