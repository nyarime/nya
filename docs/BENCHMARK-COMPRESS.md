## How to read

- **walk+greedy**: interleaved extension order (simulates unsorted solid input).
- **sorted+greedy**: extension + content-kind grouping (current `-solid` writer default).
- **sorted+optimal**: sorted order with DP optimal parser (`OptimalParse: true`).
- **writer+sort+greedy**: full `.nya` file size including header and central directory.

## Findings (CI machine, regenerate locally)

1. **Extension sorting** on the 120-file interleaved tree saves ~0.5–1.5% vs walk order at the same level.
2. **Optimal parse** is slower and **larger** on structured text and mixed solid trees here; greedy wins unless the stream is highly repetitive (see `lzma2_optimal_test.go`).
3. **Level 7 vs 9** on the solid tree: similar ratio; level 9 costs more time without a clear win on this corpus.
4. Incompressible ELF-like payloads stay at ~100% regardless of parser.
